## The envelope

```json
{ "type": "worktree.created", "time": "2026-10-03T09:12:44Z", "box": "devl", "origin": "app",
  "data": { "location": "shop", "name": "checkout", "path": "/home/me/work/shop-checkout", "branch": "checkout" } }
```

| Field | Meaning |
| --- | --- |
| `seq` | The event's number in the box's journal, in the order things happened (boxes with the `journal` capability) |
| `type` | What happened, `area.thing` |
| `time` | When |
| `box` | The box it happened on, or a laptop event's box (`box.connected`, `forward.*`) |
| `origin` | The tool it came from: `app`, `berth` (the default), `claude`, `detected`, `flow:<id>`, `guard`, `phone`, a hook's `tool`… |
| `error` | For failures |
| `data` | Depends on the type; below |

Box events reach the laptop too: the laptop agent relays every online box's
events with `box` set. `berth events` and `GET /v1/events` stream them.

A box keeps its events in a journal (`~/.berth/box/journal/`, files of up to
16 MB, at most 256 MB and 14 days in all), so nothing that follows its
events loses one in a burst, and `GET /v1/events?since=SEQ` replays what
came after `SEQ` before streaming. The laptop agent uses it to catch up after
a reconnect or a sleep.

Anything can announce its own: `berth emit TYPE key=value…` on the laptop,
`berthd emit TYPE key=value… --origin TOOL` on a box. A type is two words
of lowercase letters, digits and dashes joined by a dot, each starting with
a letter and at most 32 characters; an origin is lowercase letters, digits
and dashes.

## Box events

### Agents and sessions

| Event | Data |
| --- | --- |
| `agent.ready` | `path`, `agent`, `session` (when the hook knows it) and the tool's own id (below): a new agent at its prompt |
| `agent.started` | the same, with `signal`: `prompt` (working on a prompt) or `tool` (working again after an approval). For an agent that cannot say it started, Shipyard sends it at the send, with `source: "send"` and `turn` |
| `agent.waiting` | the same, with `reason` (`permission`, `question`): needs you. At a startup question Shipyard sends it itself, with `reason: "startup question"` |
| `agent.finished` | the same: done with its turn; `status: "error"` when it ended on a failure |
| `agent.exited` | the same: the agent itself quit |
| `task.created` | `location`, `name`, `path`, `branch`, `session`, `agent`, `from_session` |
| `session.started` | `name`, `location`, `path`, `command` |
| `session.stopped` | `name` |
| `session.memory` | `name`, `location`, `memory`, `memory_high`, `near_limit`, `text`: a session came near its [memory limit](/docs/concepts/sessions-and-agents#sessions-clean-up-after-themselves) (`near_limit: true`), or went well below it again |
| `session.renamed` | `name`: its title changed (a rename, or its first prompt named it); never the title or the prompt |
| `session.sent` | `name`, `from`, `idem_key?`, `turn?`: a prompt was typed in (never the prompt) |
| `session.queued` | `name`, `turn`: a prompt is held until the agent is idle (`when: "idle"`) |
| `session.open` | `name`, `location`, `path`, `open`, `agent`: asks the app to show a new session |
| `exec.finished` | `location`, `path`, `command`, `exit_code` |
| `preview.open` | `location`, `name`, `path`, `port`, `url_path`: an agent asks the app to show a page (`berthd preview`) |

Agent events come from the agents' own hooks (`berthd integrations install`),
with the tool as their origin and the agent's own conversation id as
`agent_session_id` (Claude Code also sends `session_id`, Codex `turn_id`,
Cursor `conversation_id` and `status`). A hook names the Shipyard session it
runs in as `session`, from `$BERTH_SESSION`. Hooks spooled while berthd was
down carry `spooled: true` and the time they ran. Shipyard does not publish a
tool use (`agent.started` with `signal: "tool"`) for an agent that is
already working: it would change nothing. When an agent's hooks cannot tell,
Shipyard reads the terminal and sends these itself with `origin: "screen"` and
`source: "screen"`. See [turns](/docs/concepts/sessions-and-agents#turns).

| Event | Data |
| --- | --- |
| `location.added` | `location`, `path`, `url` (when cloned) |
| `location.removed` | `location` |
| `worktree.created` | `location`, `name`, `path`, `branch` (origin `detected` when another tool made it); `repo_config`: `untrusted` or `changed` when the repository's config was not run because it is not trusted |
| `worktree.removed` | `location`, `name`, `path` |
| `worktree.renamed` | `location`, `name`, `path`: its display name changed (set or cleared); never the name itself |
| `worktree.setup.started`, `.finished`, `.failed` | `location`, `name`, `path`, `script`, `log` |
| `worktree.archive.started`, `.finished`, `.failed` | the same |
| `worktree.synced` | `location`, `name`, `mode`, `ok`, `base`, `conflicts` |
| `worktree.paused`, `worktree.resumed` | `location`, `name`, `path` |
| `service.started` | `location`, `name`, `path`, `service`, `port`; `session` for a service in a terminal |
| `service.stopped` | `location`, `name`, `path`, `service`; for a service in a terminal whose program ended by itself (Ctrl-C in its tab, a crash), `session` and `exit_status` |
| `service.failed` | `location`, `name`, `service`, `error` |

### Reviews

A [pull request opened for review](/docs/guides/review-a-pr). Its worktree also
has the usual `worktree.created` (with `review: true`), setup and removal
events.

| Event | Data |
| --- | --- |
| `review.opened` | `location`, `name`, `path`, `repo`, `pr`, `sha` (the commit checked out), `author`, `association` (GitHub's: `MEMBER`, `OWNER`, `COLLABORATOR`), `box`, `reviewer` (the reviewer's GitHub login), `secrets: "shared"`, `withheld` (the names of the reviewer's own keys it does not get) |
| `review.updated` | `location`, `name`, `path`, `repo`, `pr`, `from`, `sha`, `author`, `association`, `reviewer`: moved to a newer head the reviewer confirmed |
| `review.waiting` | `location`, `name`, `path`, `repo`, `pr`, `reason` (`merged`, `closed`, `idle`): due for clean-up, but it has uncommitted changes or a session running, so it waits for the reviewer; once per reason |
| `review.removed` | `location`, `name`, `path`, `repo`, `pr`, `reason`: `merged`, `closed`, `idle`, or `removed` (by hand) |
| `review.button` | `repo`, `pr`, `location`, `worktree`, and `as` and `path` when set: berthd added the [Review in Shipyard button](/docs/guides/review-a-pr#the-review-in-shipyard-button) to a PR's description, or put a new `as` or `path` in place |

| `notify` | `title`, `body`, `flow`, `path`, `location`: a flow's or the guard's notification |

| `process.stopped` | `id`, `text`: a browser (or a session) was stopped from the [box's browsers](/docs/guides/agent-browser#every-browser-on-a-box) |
| `config.changed` | what changed: `location`, `flows`, `env` or `guard`; with `location`, `trust` (`trusted` or `untrusted`) when the repository's config was trusted or no longer is |

| `skills.installed`, `skills.removed` | `skills`, `agents`, `target`, `location`, `paths` |
| `integrations.installed` | `tool`, `account?`: an agent CLI's hooks and skills were installed from the app or the API, or by berthd in an account folder a new session uses |
| `agents.installed` | `agents`: agent CLIs were added to the box from the app (**Add agents…**) or `POST /v1/agents/install` |
| `secret.failed` | `location`, `name`, `path`, `variable`, `ref`, `reason`: a [secret reference](/docs/guides/secrets) could not be read, so the variable was left unset; never the value |
| `secret.resolved` | `location`, `name`, `path`, `variable`, `ref`: one that failed reads again |
| `share.started`, `share.stopped` | `id`, `port`, `url` |
| `unit.started`, `unit.stopped`, `unit.restarted` | `name` |
| `helper.installed` | `plugin`, `name`, `version`: a [plugin's helper](/docs/guides/plugins#give-a-plugin-a-helper) was installed on the box and turned on |
| `helper.removed` | `plugin`, `purged`, `attached`: one was stopped and removed, with its data when `purged`; `attached` counts the running services that still point at it |
| `phone.changed` | `enabled` |
| `box.upgraded` | `build` |
| `pairing.invited` | `for`, `by`, `expires`: a paired laptop (`by`, as `laptop:<name>`) asked for a pairing code for another computer (`berth invite`); never the code |
| `client.paired` | `name`, `fingerprint`: a laptop paired with the box |
| `client.revoked` | `name`, `fingerprint`: a laptop removed from the box from another one (Settings → Computers) |

Flows triggered by a schedule, GitHub or a webhook receive `schedule.fired`,
`github.review_comment`, `github.pr_review`, `github.check_failed`,
`github.pr_merged`, `github.issue_labeled`, `github.issue_assigned` or
`webhook.received` as their event; these start the flow directly and are not
announced to hooks.

A flow's `scope` is `box` or `repo:<location>`, whichever layer (committed,
kit or the box's own) the flow comes from; only the flow that wins its `id`
runs, so `flow` and `scope` name one flow.

## Gates

Gates are `before:` hooks on a box. They run before the action, in order
(the box's `hooks.json` and plugins, then the repository's), and one that
exits non-zero refuses it with what it printed. Gates in a laptop's
`hooks.json` never run.

| Gate | Data |
| --- | --- |
| `before:location.add` | `location`, `path`, `url` |
| `before:worktree.create` | `location`, `name`, `branch`, `base`; for a [review](/docs/guides/review-a-pr) also `review: true`, `repo`, `pr`, `sha` |
| `before:worktree.remove` | `location`, `name`, `path` |
| `before:worktree.rename` | `location`, `name`, `title` (`""` clears it) |
| `before:worktree.sync` | `location`, `name`, `mode` |
| `before:worktree.pause`, `before:worktree.resume` | `location`, `name` |
| `before:task.create` | `location`, `name`, `branch`, `base`, `agent`, `command` |
| `before:session.start` | `name`, `location`, `path`, `command` |
| `before:session.stop` | `name` |
| `before:session.send` | `name`; from the phone also `from: "phone"`, and `key` for a key press |
| `before:exec` | `location`, `path`, `command` |
| `before:run.start` | `template`, `path`, `steps`, or `flow`, `scope` |
| `before:run.approve` | `run`, `step`, `approve`: deciding a gate, from the app, CLI or phone |
| `before:run.cancel` | `run` |
| `before:run.pr` | `run`, `path`, `branch`: a run about to push and open a pull request |
| `before:artifact.add` | `location`, `name`, `path`, `title`, `kind`, `id` (when updating one) |
| `before:artifact.remove` | `location`, `name`, `path`, `id` |
| `before:browser.open` | `location`, `name`, `path`, `url`: an agent browser opening a page |
| `before:browser.eval`, `before:browser.watch` | `location`, `name`, `path`: running JavaScript in it, watching it live |
| `before:browser.allow` | `origin`: letting agents' browsers load a public origin |
| `before:worktree.login` | `location`, `worktree`, `email`: logging a worktree in as a dev user from the laptop (`/__berth/login`) |
| `before:process.stop` | `id`: stopping a browser or session from the box's browsers list |
| `before:kit.install` | `location`, `kit`, `source` |
| `before:kit.remove` | `location` |
| `before:team.setup` | `team`, `org`, `commit`: a team setup about to start on the box |
| `before:team.retry` | `team`, `from` |
| `before:skills.install`, `before:skills.uninstall` | `skills`, `agents`, `target`, `location` |
| `before:integrations.install` | `tool` |
| `before:config.change` | `location`, `flows`, `env` or `guard`: what is about to change |
| `before:phone.change` | |
| `before:location.remove` | `location` |
| `before:hooks.change` | |
| `before:session.attach` | `name` |
| `before:service.start`, `before:service.stop`, `before:service.restart` | `location`, `worktree`, `service` |
| `before:unit.start` | `name` |
| `before:unit.stop`, `before:unit.restart` | `name` |
| `before:share.start` | `port` |
| `before:share.stop` | `id` |
| `before:flow.test` | `flow`, `scope` |
| `before:box.upgrade` | `build` |
| `before:helper.install` | `plugin`, `name`, `version`: a paired laptop installing a plugin's helper, a program that will run on the box |
| `before:pairing.invite` | `for`, `by`: a paired laptop asking for a pairing code for another computer |
| `before:client.revoke` | `name`, `fingerprint`: removing a laptop from the box |
| `before:event.emit` | `type` |

A gate's `BERTH_EVENT_ORIGIN` is what the box can vouch for: the tool named by
a caller on the box's own socket, or `laptop:<name>` for a paired laptop and
`remote` for the phone, whatever origin they claim. So a gate scoped to a
`tool` cannot be skipped from another machine by claiming to be that tool.
Gates stop mistakes and keep automations inside the lines you draw; they are
not a boundary against a paired laptop, which can already run commands on the
box.

A task runs `before:task.create`, then the worktree's and the session's own
gates.

## What a hook gets

| Variable | Meaning |
| --- | --- |
| `BERTH_EVENT` | The event's type |
| `BERTH_EVENT_BOX` | Its box |
| `BERTH_EVENT_ORIGIN` | Its origin |
| `BERTH_<FIELD>` | Each data field, upper-cased, with other characters as `_`: `BERTH_PATH`, `BERTH_NAME`, `BERTH_LOCATION`, `BERTH_SESSION`, `BERTH_AGENT`… |
| `BERTH_ORIGIN` | The hook's `tool`, or `hook`: Shipyard commands the hook runs announce their events with it |
| `BERTH_PLUGIN_DIR` | A plugin's hooks: its folder |

The event is also on stdin as JSON. Hooks from a repository's config get the
worktree's environment as well; see [files and environment](/docs/reference/files#environment).
